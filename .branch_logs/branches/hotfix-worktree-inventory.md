# hotfix/worktree-inventory

- Base: main v0.20.8, commit 4cfcb70654ead592f228621472d154b2577a52d1. Prepare patch 0.20.9 through hotfix -> dev -> main and immutable tagged Release/Brew distribution.
- Root cause: sibling/submodule expansion and history hydration repeated the same Git work within one scan. The observed Vox pass issued 1,231 Git commands (169 distinct directory/argument combinations) and took 3.135 seconds, exceeding the two-second worktree RPC budget. The multiplication predates this incident; retained evidence does not establish the exact historical growth event or prove that a recent release introduced it.
- Backend: share a request-local WorktreeScan across discovery/history, deduplicate family expansion before expensive work, reuse metadata/config queries, and skip already scanned historical paths. New requests observe changed Git state; no global cache or project registration changes. Give only the worktree RPC four seconds; leave health/action budgets unchanged.
- Grouping: all 15 observed Vox worktrees share one verified common Git directory, but two branches lack the explicit repository config and retain a fallback ID. Add host-authoritative display identity fields when the family has one unambiguous explicit identity. Preserve raw IDs, routing, Compose identities, independent/logical roots, history v1 and project files; do not choose among conflicting explicit identities/names.
- UI: show one-root branches directly, retain multiple-root distinctions and root Details, distinguish stopped from host-confirmed deleted, expose refresh progress/last successful scan/Refresh/Retry, and mark retained inventory as last-known when the agent is unavailable. Start stays disabled for incomplete inventory; current service endpoints/actions remain sourced from current data. Clear snapshots on target changes or successful empty scans and reject superseded responses.
- Independent GPT Sol 6.1 backend verification: 172 passed, one existing opt-in real Compose test skipped, zero failures. Additional in-memory probes verified the catalog never inspects host paths locally, display fields survive transport projection, raw routes remain unchanged, and the resolver override preserves caller precedence.
- Actual-Git immutable 16-worktree fixture: baseline 846 Git commands/1.763061 seconds; candidate 100/0.171987 seconds. Ordered raw records were identical after excluding only the two new display fields. Fourteen explicit configs distinguish this fixture from earlier scaling measurements.
- One read-only candidate pass on Vox: 171 Git commands/0.426282 seconds; 15 rows, one display identity/common root, dev stopped and startable, all five services enriched. Candidate modules were isolated from installed modules; history writes were suppressed only in that process and the real history hash was unchanged. This is instrumented candidate verification, not installed HTTP latency or deployment proof.
- Emergency boundary: the user separately authorized the already completed installed 0.20.6 worktree-RPC timeout change from two to four seconds and one owned catalog restart. That temporary package is not a clean upstream 0.20.6 installation. Permanent deployment must replace it through verified 0.20.9 Release/Brew, not another installed-source patch. No business containers, training, Git files, Pod, DNS/Tailscale or other machines are changed by this implementation.
- Independent Chromium verification passed against the backend-emitted Vox fixture and isolated API responses: grouping, stale/unknown/empty/recovered inventory, target-switch races, disabled Start plus its actual handler, fresh service actions, coalescing/15-second polling, existing update feedback and the English guide. A real 390px overflow in full configuration-error text was found and fixed by wrapping, not truncating; focused light/dark rechecks passed. This was a loopback harness, not production UI deployment proof.
- Frontend build ran once successfully; compiled catalog assets are included and the canonical project-integration Skill is unchanged. Verification used GPT Sol 6.1 with no fallback model.
