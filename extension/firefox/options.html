Compatible Firefox networking required

Both direct and SSH connections require working experimental networking APIs. Use a Firefox build that permits extension experiments. Where available, enable extensions.experiments.enabled in about:config before installing this extension. If you installed it with experiments disabled, enable the setting, restart Firefox, and reinstall the experimental XPI; restarting alone may not register its APIs. If your Firefox rejects the package or cannot provide these APIs, switch to a compatible build. Changing connection settings cannot add networking capabilities.

Firefox experimental-build downloads · Firefox Nightly for Android. Availability is decided by the working networking APIs, not the browser name or version.

No connection will fall back to ordinary direct browsing or an external proxy. Your saved connections are kept. All .portmap traffic remains blocked until capability is available.

Local configuration needs attention

Legacy SOCKS5 connections cannot be converted into direct or SSH connections. Stored data is not silently changed. If this is an old configuration, record the endpoints you need, use “Reset all local connections” below, then rebuild with explicit HTTP/HTTPS ports and, for SSH, verified credentials and a trusted host fingerprint. Reset permanently deletes the saved local configuration.

Add connection

Enter a node name such as voxmani to fill its domain and host. Addresses follow the name only until you edit them manually. Renaming a saved connection never changes its endpoints. A short host requires working name resolution; otherwise use its actual IP or hostname.

Connection settings

Matches this exact domain and its descendants, such as app.node.portmap. Overlapping connections are not allowed, including disabled ones.

Use a reachable IP address or hostname, not a URL or .portmap name. Direct mode connects to this destination; SSH mode connects to this SSH server. The extension never starts a workspace or changes system DNS, VPN or routes.

Enter the node's real HTTP port. HTTPS is enabled only when you explicitly supply its port; leave it blank otherwise. In SSH mode these ports are reached at the target host through the tunnel. Direct TCP adds no encryption: use a trusted encrypted network for HTTP.

SSH server and trust

The ordinary hostname or IP that the SSH server should connect to, usually 127.0.0.1. This is an address, never a shell command.

Obtain and verify the SSH host key fingerprint through a trusted channel before saving. Accepts OpenSSH SHA256:base64 or 64 hex characters. No first-use trust or accept-any option is provided.

Replacement SSH credentials

Use an RSA private key in PEM format (BEGIN RSA PRIVATE KEY) and its matching OpenSSH ssh-rsa public key. OpenSSH private-key format and Ed25519 keys are not supported. Files are read locally and saved only when you save the connection.

Local configuration, explicit routing

Connections, SSH passwords, private keys and passphrases stay in this Firefox profile's local extension storage, not Firefox Sync. They are not encrypted by this extension. Protect your profile and use only trusted SSH servers. Stored secrets are never displayed in connection cards; editing keeps them unless you explicitly choose a replacement. No analytics or central connection manager is used.

Unconfigured or disabled .portmap addresses are blocked, including while connections load or change. Other websites retain Firefox's normal network behavior. Allow this extension in private windows if you need routing and blocking there; it cannot protect windows where Firefox disables it. Disabling or uninstalling the extension removes its protection.

Open node uses HTTP by default. HTTPS is available only with a configured HTTPS port and a trusted certificate for the original .portmap name at the node. No TLS verification is bypassed. Direct HTTP traffic is visible on the network path; SSH encrypts traffic to the SSH server, which can observe forwarded HTTP traffic.
